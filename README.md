## API

Все методы требуют заголовки `Authorization: Bearer <токен>` и `Accept: application/json`. Без `Accept` запрос без токена вернёт 500 вместо 401.

| Метод | Адрес | Что делает |
|---|---|---|
| GET | `/api/bookings` | Мои брони |
| POST | `/api/bookings` | Создать бронь |
| DELETE | `/api/bookings/{id}` | Отменить бронь |
| GET | `/api/rooms/{room}/bookings/today` | Брони комнаты на сегодня |

Пример:

    curl -X POST http://localhost:8000/api/bookings \
      -H "Authorization: Bearer anna-token" \
      -H "Accept: application/json" \
      -H "Content-Type: application/json" \
      -d '{"room_id": 1, "user_id": 1, "title": "Планёрка", "starts_at": "2026-11-02T10:00:00+03:00", "ends_at": "2026-11-02T11:00:00+03:00"}'

Лог созданных броней пишется в `storage/logs/bookings.log`.

## Формат времени и таймзоны (строго)

`starts_at` и `ends_at` принимаются **только в ISO 8601 со смещением**:
`YYYY-MM-DDTHH:MM:SS±HH:MM` или `YYYY-MM-DDTHH:MM:SSZ`.

Примеры валидных значений:

- `2026-11-02T10:00:00+03:00` — Москва (UTC+3)
- `2026-11-02T14:00:00+07:00` — Новосибирск (UTC+7)
- `2026-11-02T07:00:00Z` — то же, что 10:00 MSK

Примеры **невалидных** значений (вернут 422):

- `2026-11-02 10:00:00` — пробел вместо `T`, нет смещения
- `2026-11-02T10:00:00` — нет смещения (интерпретация «локально» запрещена:
  сервер не угадывает офис по комнате, смещение обязательно)
- `02.11.2026 10:00` — не ISO 8601
- `2026-11-02T10:00:00+25:00` — несуществующее смещение

**Почему строго.** Офисы в разных таймзонах (Europe/Moscow и
Asia/Novosibirsk), и клиент может присылать время в любом смещении. Сервер
нормализует значение в UTC (`CarbonImmutable` / `timestamptz` в PostgreSQL),
а рабочие часы 09:00–20:00 проверяет уже **в таймзоне офиса комнаты**, а не в
таймзоне клиента. Без явного смещения в запросе эту проверку сделать
однозначно нельзя, поэтому формат со смещением — обязателен.

Внутри БД поля хранятся как `timestamptz` (UTC), при выдаче в `index`/`today`
сериализуются обратно в ISO 8601 с `Z` — фронт должен парсить их как UTC и
конвертировать в локальную таймзону пользователя самостоятельно.

## Интеграция с фронтендом

API stateless, авторизация — Bearer-токен (Sanctum). Фронт должен:

1. **Слать `Accept: application/json`** во всех запросах. Без него Laravel
   попытается отрендерить HTML-ошибку, и неавторизованный запрос вернёт 500
   вместо 401 — это известное поведение скелета, не баг API
   (см. раздел «API» выше).
2. **Слать `Content-Type: application/json`** на `POST`.
3. **Токен** — в заголовке `Authorization: Bearer <токен>`. Токены из сидера
   (`anna-token`, `boris-token`) годятся только для локальной демонстрации;
   в проде — выдача через Sanctum.
4. **Время — только ISO 8601 со смещением** (см. раздел «Формат времени и
   таймзоны»). Фронт может слать время в таймзоне пользователя — сервер
   нормализует.
5. **Обрабатывать 422** как ошибку валидации с полем `errors` — формат
   стандартный для Laravel `ValidationException`:

   ```json
   {
     "message": "The starts at field must be a valid ISO 8601 datetime with offset.",
     "errors": {
       "starts_at": ["..."]
     }
   }
